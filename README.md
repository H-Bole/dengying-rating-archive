# 灯影刘肉丝电影评级档案

整理 B站 UP 主「灯影刘肉丝」（UID `4140446`）当前公开动态中的电影评级，默认按上映时间归档，也可切换为评分时间，保留原始表述与调级历史，方便检索和回看。

这是一个非官方静态档案，不代表 UP 主或 B站的官方立场。

**[在线浏览](https://h-bole.github.io/dengying-rating-archive/)** · **[原始动态](https://space.bilibili.com/4140446/dynamic)**

## 可以做什么

- 按片名、别名、电影正式片名或原名搜索。
- 在上映时间与评分时间之间切换，年份分组、年份筛选与排序同步变化。
- 组合筛选所选时间轴的年份、当前评级等级和上中下细分，切换时间顺序。
- 查看电影海报、上映日期、导演、主演、片长和简介。
- 展开评分来源与修订记录，查看同一部电影的历次评级。
- 将完整仓库下载到本地后，离线浏览和搜索。

截至 **2026 年 10 月 27 日**，档案包含 **164 部电影、170 个评级事件**，历史采集共审阅 **462 张动态卡片**。电影数、评级事件数和动态卡片数分别统计，一张卡片可能涉及多部电影。

## 本地打开

下载或克隆完整仓库，直接用浏览器打开根目录的 `index.html` 即可。请保留其他文件与 `assets/posters/` 的相对位置。

无需安装依赖、构建项目或启动后端。页面使用原生 HTML、CSS、JavaScript，数据和海报随仓库保存；浏览站点不需要配置 TMDB API Key。

离线时仍能搜索、筛选和查看已保存资料，跳转 B站来源链接需要联网。

## 数据收录规则

- 只收录本人公开内容中具有明确电影名和明确评级的记录，不从评论、视频标题或模糊好恶推断评级。
- 正式八档为 **天、地、玄、黄、破、烂、溜、丢**，上中下等单独保存。
- 「一口钟」「软泥怪」等特殊评级原样保存，不强行归入八档排序。
- 新评级追加到历史，不覆盖旧评级；暂定、明确评级和调级保留各自状态。
- 每条记录仅保存核验所需的一至两句短摘录，不转载完整动态、图片或视频。

时间线默认按**上映日期**排列，可切换至**当前评级的发布日期**；卡片分别标注两类日期。切换时间轴会清空已选年份，其他筛选与排序方向保留；“清空条件”保留当前时间轴，刷新或重新打开页面恢复上映模式。电影内部的评级历史始终按评分日期最新在前展示。

上映日期沿用现存电影资料，地区与首映／院线类型尚未逐条校准。缺失或无效日期单独归入末尾“上映日期未收录”组，不使用评分日期替代。

「全历史」仅指采集时当前公开可访问的内容，不包含已删除、隐藏或无法核验的编辑前版本。部分历史记录没有单条动态永久链接，使用作者动态页、日期和摘录定位；已核验到单条链接的记录提供直达入口。

## 后续增量更新

仓库内置 Codex 技能 [dengying-incremental-update](.agents/skills/dengying-incremental-update/SKILL.md)，检查点保存在 [data/update-state.json](data/update-state.json)。技能属于本项目，无需安装到系统级目录。

在 Codex 中打开本仓库后，可以直接说：

> 使用 $dengying-incremental-update 更新灯影评级档案。

更新流程从最新动态开始，读到上次保存的动态 ID 边界即停止，统计期间新增的动态及其收录、排除情况，再归纳新电影和旧电影的新评级。默认包含新增电影资料补齐、网站验证、提交和发布到现有 GitHub Pages。

首次边界校准已完成，保存了主锚点及相邻备用锚点。首次校准不报告无法证明的精确新增数量；后续更新根据已保存动态 ID 去重和对账。

如果旧锚点被删除或隐藏，且备用锚点仍无法确认边界，更新会保留原检查点并报告缺口，由维护者决定是否扩大回查。日常增量不重新遍历全部历史，也不检测旧动态的原地编辑；两次检查之间已发布又删除的内容无法保证发现。

采集使用正常浏览器只读访问与人工复核，不保存账号凭据，不绕过验证码、风控或 HTTP 412，不运行长期无人值守爬虫。
